## Findings

### Confirmed against the live gateway

- Auth `Authorization: Bearer`, base `https://api.hyperouter.app/v1`, error body `{error:{message,type,code,param}}` (seen on 401 and 400).
- Image create with `Prefer: respond-async` answers `202 {id,status:"queued"}`; `GET /v1/generations/{id}` moves `submitting` → `done` (the `queued`/`running` states were not observed for this image, it sat in `submitting` for about 20 s); `outputs[].url` is a signed R2 link and `expires_at` is RFC 3339, 24 h out; `usage.cost` is a JSON number.
- `POST /v1/videos` answers the Video object; `in_progress` with `progress` 0 → 50 → `completed` 100; `usage.cost` set on completion; `GET /v1/videos/{id}/content?variant=video` answers 302 to a signed R2 link (15 min). `variant=thumbnail` answered 404 for Seedance 2.0 Mini (no thumbnail), which the adapter treats as optional.
- `Idempotency-Key` accepted on image, video and chat creates (our `job_…` / `msg_…` ULIDs).
- Chat SSE: OpenAI chunk format; DeepSeek streams `delta.reasoning_content` before the answer (reasoning is on by default); `tool_calls` deltas arrive by `index` with `id` + `name` first and `arguments` in many small fragments; `finish_reason: "tool_calls"`; a final chunk with empty `choices`, `usage` incl. `cost` and `provider: "DeepSeek"`; then `data: [DONE]`.
- **Tool names must match `^[a-zA-Z0-9_-]{1,64}$`.** A tool named `pricing.estimate` got `400 invalid_body` ("Every provider for this model refused the request as invalid"). The adapter now sends dots as `__` and maps names back, so harness tool names keep their dots.
- `GET /v1/models` returns more than the docs show: `param_schema` (allowed values, min/max, `exclusive` groups), `prices` (per meter with conditions such as resolution, `video_input`, `min_pixels`, `input_images`), `input_image_required`, `edit_only`, `min/max_input_images`, `request_example`. Capabilities were built from this.

### Not confirmed (tested only with mocks)

- Webhooks (no endpoint registered): signing scheme implemented per Standard Webhooks and the docs, verified only with locally signed payloads.
- 402, 429 + `Retry-After`, 503 + `x-should-retry: false`, the three 409 idempotency codes, mid-stream chat errors, failed jobs: mapped per docs, exercised by unit tests only.
- `moderation: "low"`: never sent. The docs say it needs account enablement (`403 moderation_not_enabled` otherwise) and is silently ignored on models without a vendor opt-out.
- The meaning of Seedance's `video_input` price condition (lower per-second rate plus a per-ms input charge) — assumed to apply when `reference_videos` are sent; capabilities use the higher, text/image-driven rate.

### Docs/PRD vs live gateway

- Seedance 2.5: 4–15 s (PRD says up to 30 s); 480p/720p/1080p; audio; up to 9 image + 3 video + 3 audio refs; keyframes and reference media are mutually exclusive.
- MiniMax H3: 768p or 2K, **no audio**, 5 image + 3 video refs (PRD: native audio, 9 + 3 + 3).
- Wan 3.0: 2–30 s, 480p–1080p, audio, docs/web page input via `file` / `link`; no `extend` operation (PRD lists extend).
- Seedance 2.0 Mini is the cheapest launch-grade video: $0.035154/s at 480p (the docs table shows the lower `video_input` rate, $0.0210924/s).
- Seedream 5.0 Lite costs $0.035/image, more than `seedream-5.0-flash` ($0.018) and the new `seedream-5.5` ($0.02, $0.035 at ≥ 2.6 MP). Seedream models take no `seed`, `negative_prompt`, `ratio` or `resolution` (only `size`, `prompt_expand`); sending them is a 400.
- New ids not in the brief: `bytedance/seedream-5.5` (proposed Seedream "Pro" substitute, marked `substituteFor: seedream-5.0-pro`, needs product sign-off), `bytedance/seedance-2.5-flash`, `alibaba/wan3.0-turbo|-pro|-pro-turbo`, `bytedance/seedance-2.0`, the `lumina/*` family and `x-ai/grok-imagine-*`. See the diff below.

### Mature routing (D-005)

- Every model ships `mature: false`. The `lumina/*-spicy` models (`z-image-spicy`, `z-image-spicy-pro`, `qwen-image-edit-spicy`, `wan2.2-i2v-spicy`, `wan2.7-i2v-spicy`) are in capabilities as candidates; only their name suggests adult output — the metadata has no description or flag that says so — so they stay `mature: false` with a note until Hyperouter confirms. `qwen/qwen-image-2.0` lists `moderation` in `supported_parameters`, a hint that it has a vendor screening opt-out; not confirmed.
- Face/head swap models (`lumina/face-swap`, `lumina/head-swap`, `lumina/video-face-swap`, `lumina/video-head-swap`) and the photo-driven `lumina/wan-animate` / `lumina/wan2.7-i2v-spicy` carry `requiresIdentitySafety: true`. `isMatureRoutable()` is false for them whatever `mature` says, `moderationFor()` throws `MatureRoutingError`, and `pickAuto()` never selects them. D-005 forbids sexual or intimate content depicting a real, identifiable person; these models exist to put a real face into an image or clip, so they must never be reachable from a mature run, and every use needs the identity checks in `packages/core/safety`.

### Avatar / lip sync gap

- `lumina/wan2.7-i2v-spicy` takes a start picture plus `audio_url` (WAV/MP3, 2–30 s) and lip-syncs to it (720p/1080p, 2–15 s, $0.13/s at 720p). It is the only avatar-like path on the gateway; recorded as a candidate `substituteFor: wan-2.2-s2v`. It still needs a voice track from somewhere else: there is no TTS or voice cloning on Hyperouter.
- `lumina/wan-animate` is motion transfer (a picture's character follows a driving clip, `mode` animate|replace), not lip sync.
- `lumina/face-detect` (chat-kind, $0.0013/request) returns face boxes; potentially useful for the real-person checks in `core/safety`.

### Credit pricing sanity (placeholders vs gateway cost)

Placeholder credits per 5 s are flat across resolutions, but gateway cost is not: Seedance 2.5 costs $0.54 per 5 s at 480p and $2.84 at 1080p for the same 8 credits; Wan 3.0 $0.25 vs $1.00 for 7 credits. Credit prices need a resolution (and audio) dimension before launch, or a credit-to-USD rate that covers the most expensive option. `CREDIT_TO_USD` is still `[PRICE]`.

### Recommendation: tool-call streaming

Use native streamed tool calls with DeepSeek v4.1 Flash; no JSON-mode fallback needed. The spike's single call picked the tool unprompted, streamed the arguments in 23 fragments, and the assembled arguments parsed as JSON and matched the schema (with the optional `resolution` filled). Keep the fallback (`responseFormat: json_object` parsed against the same Zod schemas) as a switch in the agent, and validate every assembled call with Zod regardless. One spike call is not a reliability measure: the M6 eval suite should track tool-call validity rate. Set `reasoningEffort: "none"` for patch/tool turns if latency matters (reasoning is on by default and billed inside `max_tokens`).

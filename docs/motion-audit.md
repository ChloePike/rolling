# Motion audit (2026-11-27)

A pass over every animated or transitioning surface, against `CLAUDE.md` (CSS transitions; `motion` only for layout animation; no decorative motion; respect `prefers-reduced-motion`) and `docs/design/handoff.md` §7 (durations instant 80 / fast 140 / base 200 / slow 320 / brand 400 ms; standard curve to enter or move, exit curve and a shorter time to leave; movement 4–16px, scale ≥ .96; lists stagger 30ms, max 6; reduced motion: opacity only).

## Method

The mock build (`VITE_API_MODE=mock`) at 1440×900, dark and light, `prefers-reduced-motion` on and off (4 runs per surface). A Playwright script recorded every `animationstart` / `transitionrun` with the element, property or keyframes, duration, delay, curve, iteration count and whether it moves (the element's transform sampled at the first, middle and last frame), plus `layout-shift` and `longtask` entries, and took frame samples (`page.screenshot` every 40–200ms) of each interaction, which were looked at one by one. Interruption was checked by toggling a popover four times in 120ms, hovering in and out within 20ms, switching routes every 40ms and closing dialogs while they enter. Performance: 66 canvas nodes panned and zoomed (wheel and ctrl+wheel) and Home with 12 run cards scrolled, with a CDP CPU profile, a `requestAnimationFrame` frame log and the long-task observer.

Commits: `42c8204` (tokens, helpers, skeleton, build stagger, theme switch), `47ea6a1` (components on the tokens, CSS-module keyframes), `a65ab0d` (canvas), `1fca928` (guard), `4d38b68` (e2e). The checks that came out of it are now permanent: `apps/web/e2e/motion.spec.ts` (reduced motion and token timing on seven key surfaces, layout shift on Home and Canvas load and on a theme switch, the canvas prompt panel tracking its node), `apps/web/e2e/stubbed-real/motion.spec.ts` (skeleton delay under reduced motion, Home skeleton → content without shift) and the source guard `apps/web/scripts/check-motion.mjs` run by `apps/web/src/styles/motion-tokens.test.ts`.

## Centralised motion

- **Tokens** (`packages/ui/tokens.css`): the handoff durations and curves (`--dur-*`, `--ease-*`, `--m-*`), plus what the app needed beyond them: `--m-build-stagger` (150ms), `--m-skeleton-delay` (150ms), `--m-follow` (120ms, live pointer smoothing), `--m-crossfade` (600ms, login showcase), the status loops `--m-loop-pulse/typing/spin/indeterminate/blink` with `--ease-loop`, and `--dur-reduced` (200ms). Under reduced motion every movement and scale token is zero, the build stagger is zero and `--m-slow`, `--m-brand` and `--m-crossfade` collapse to 200ms, so no fade is longer than `--dur-reduced`.
- **Helpers** (`@rolling/ui`): `duration` / `easing` (JS mirror, now with `crossfade`, `buildStagger`, `skeletonDelay`, `reduced`), `bezier` and `tween()` for the one `motion` layout animation, `motionMs()` for JS-driven motion (canvas pan/zoom/fit) that returns 0 under reduced motion, plus the existing `usePresence`, `presenceProps`, `staggerStyle`, `useIndicator`, `usePrefersReducedMotion` and the `rl-*` classes in `base.css`.
- **Guard**: `check-motion.mjs` fails on a literal time or curve in any `transition*` / `animation*` declaration (CSS modules, `base.css`), inline style strings and keys, `${…}ms` computed in a style string, `motion` transitions (`duration`, `ease`), `usePresence(open, 140)`, React Flow viewport calls with a numeric `duration`, and a shared `rl-*` keyframe named from a CSS module without `global()`. `0`, `none`, `linear` and `var(…)` pass. One allowlisted file: `Splash.module.css` (the brand choreography of `Splash.dc.html`; its exit and reduced-motion fade use tokens).

## Findings

Status: **fixed** (commit), **open** (with the reason), **ok** (checked, nothing to change).

### Checked and fine

- **Routes**: no route-level transition (instant swap); new content enters with the list stagger (200ms rise, 30ms apart, max 6). No layout shift on Home, Canvas, Activity, Assets or Quick Create loads (CLS ≤ 0.0005).
- **Popovers and menus**: 200ms from 6px on the standard curve, out in 140ms on the exit curve; four toggles in 120ms end closed and unstuck; Escape mid-enter closes cleanly (closing layers are `inert` and `aria-hidden`).
- **Tooltips**: 140ms enter from 4px, unmount on leave; fast hover in/out leaves nothing behind.
- **Modals** (UpgradeModal, AssetPicker, template preview, RunConfirm): 320ms rise + scale from .96, overlay fade 200ms, out in 140ms on the exit curve; focus moves into the dialog on open and returns to the trigger on close (`ux-audit` #2).
- **Toasts**: rise 12px over 200ms, fade out 140ms; the failure toast and the card update together.
- **Run cards**: queued → generating (elapsed time, indeterminate or real progress) → done (result fades in over 200ms in place) or failed (copy + Retry + toast); no movement after the card's entry.
- **Canvas**: selection is a 140ms ring/box-shadow change; run state labels fade; a version switch fades the result in place (200ms); wire highlight 140ms.
- **Editor and timeline**: drawn on `<canvas>`; the playhead follows playback per frame (content, not decoration); no CSS motion runs during play.
- **Template cards**: hover is a 140ms ring, no zoom or autoplay.
- **Upgrade success**: a toast and the card turning into “Current plan”; no celebration motion.
- **Transfers dock**: ring progress on `stroke-dashoffset` (linear, real progress), off under reduced motion; panel uses the shared popover motion.
- **Reduced motion across all of the above**: no movement or scale, no loops, fades ≤ 200ms; smooth scrolls become instant.
